# Gmail → univ合同会社 顧客向け物件資料化・配信フロー

## 目的
提携先・売主側担当者からGmailで受領した物件情報を、紹介許可が確認できている案件について、univ合同会社の顧客向け資料へ短時間で変換し、Google Driveへ保存したうえで顧客へ配信する。

## 完了条件
1. 元メール本文と添付を取得。
2. 原本をDriveへ非破壊保存。
3. PDFの物件事実（物件名、価格、利回り、所在地、面積、構造、築年等）を変更しない。
4. 元会社の営業用ロゴ・問い合わせ用ブランド表記だけをuniv合同会社へ差し替える。
5. 元資料が「保有物件」等の権利主体を示す表現の場合、univが所有者であるように書き換えず、「univ合同会社 ご紹介物件」等へ変更する。
6. 紹介許可が個別に確認済みの案件では、元資料の一般的な第三者紹介禁止文言を顧客向け紹介文言へ差し替える。
7. PDFを再レンダリングし、欠け・重なり・文字化けを確認する。
8. 原本と完成版を画像差分比較し、意図したヘッダー／フッター以外の変更がないことを確認する。
9. 元メール本文から、担当者宛の挨拶・署名・社内向け文言を除き、物件情報だけを顧客向けメール本文へ再構成する。
10. 顧客向け完成PDFのみを添付して送信する。
11. 送信済みメールID、DriveフォルダID、成果物URLをログへ残す。

## City Homesプロファイル
現行スクリプト: `tools/property_whitelabel_pdf.py`

```bash
python tools/property_whitelabel_pdf.py \
  source.pdf \
  customer.pdf \
  --profile cityhomes
```

### 自動編集内容
- CITY HOMESロゴ／営業ブランド欄 → `univ合同会社`
- `株式会社シティホームズ 保有区分マンション` → `univ合同会社 ご紹介区分マンション`
- `本物件情報は貴社限りとし、他社への物件紹介はご遠慮ください。` → `本資料はuniv合同会社のご紹介資料です。最新状況はお問い合わせください。`
- その他の物件データは変更しない。

## Gmail本文の顧客向け再構成ルール
本文は以下の順にする。

1. 宛名・挨拶
2. 「物件情報を共有します」等の要件
3. 主要物件の名称、価格、利回り、所在地、交通、面積、構造、築年／竣工予定
4. 詳細は添付資料参照
5. 「ご興味のある物件があれば最新の販売・賃貸状況を確認します」
6. 簡潔な署名

元メールに含まれる仕入先担当者の署名、広告案内、訪問予定、仕入先社内向けの案内文は顧客メールへ転記しない。

## 保存先ルール
標準:
`0.物件資料_お客様紹介用 / 資料請求_自動保存 / YYYY / YYYY-MM-DD__仕入先_担当者_顧客案内用`

その配下に:
- `01_原本`
- `02_顧客案内用_univ合同会社`

を作り、原本と完成版を混在させない。

## QA
最低限以下を機械確認する。
- PDFページ数が一致
- `univ合同会社` が完成版に存在
- 元の第三者紹介禁止文言が完成版に残っていない
- 権利主体を誤認させる元ヘッダーが残っていない
- レンダリングで文字化け・欠け・重なりがない
- 差分が意図したヘッダー／フッター中心に限定
- Driveアップロード後に親フォルダとファイル名を再取得
- Gmail送信結果を再確認

## 追加プロファイル
別仕入先の資料は、同一スクリプトに新しい `profile` を追加する。座標を無理に共通化せず、仕入先ごとの既知レイアウトを小さなプロファイルとして管理し、物件事実の変更を禁止する共通QAだけを共有する。
